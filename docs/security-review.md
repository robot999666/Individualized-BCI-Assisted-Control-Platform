验证日期：2026-09-29。范围：当前 `backend/`、`frontend/` 与 `deploy/`。页面文案、业务数据、模型文件、算法参数与角色权限保持现有设置；既有 README 和交付材料未改动。

## 检查结果与修复

| 项目 | 防护与验证 |
| --- | --- |
| SQL 注入 | 检查到的数据库查询均使用 SQLAlchemy 参数绑定，`text()` 仅执行固定健康检查 SQL。测试恶意登录、用户名与对象 ID，不将用户输入拼入 SQL。 |
| XSS | 用户名称、回答与日志继续通过 React 文本节点显示，未引入 HTML 拼接。生产构建自动生成静态脚本 SHA-256 白名单，不允许任意内联脚本、事件属性或 eval；同时限制对象、表单目标与资源来源。浏览器实测恶意 img 文本未生成图片元素、未弹窗。 |
| 输入与请求溢出 | 登录账号 80 字符、密码 128 字符，参与者名称和来源标识 80 字符，问题 500 字符；JSON 16KiB、嵌套最多 64 层、网址与请求头有上限。校验错误省略输入内容，避免回显密码。 |
| 上传与数组内存 | 请求解析前同时检查声明长度与实际流量；请求体先暂存，内存缓冲最多 1MiB。EEG 文件 20MiB，EOG 配对 16MiB，EOG 单窗口 16KiB。数组读取前检查 NPY 头、精确负载长度、数值类型及整数尺寸计算；NPZ 禁止重复成员、额外成员、对象数组与非法路径，解压和 float64 转换均受 64MiB 上限约束。畸形 DEFLATE 返回校验错误。 |
| 多用户与资源竞争 | 密码计算最多 2 个并发任务并移出事件循环；批量请求最多 2 个，拒绝超额排队；取消请求后仍等待计算线程结束才释放容量。共享演示账号的会话替换和退出清理按登录客户端隔离，其他访客不会被关闭。跨账号读取、上传、控制与 WebSocket 继续执行所有权和角色检查。 |
| 实时连接与回收 | 每会话最多 3 条实时连接，发送阻塞 5 秒后回收。最多 100 个活动会话、信号数组合计 512MiB；无连接且闲置 30 分钟的暂停/完成会话自动释放数组。会话容量拒绝不会替换正在工作的会话。过期登录令牌定期删除，每账号最多 100 个有效客户端登录。 |
| 访问频率与 CSRF | 请求频率限制采用有容量上限、不会因键数量过多而清空的计数器；登录最多每 IP 每分钟 8 次。生产写入保留 Origin 白名单和自定义请求头，并拒绝缺少 Origin 的跨站请求。停止和控制保留独立容量和频率配额。 |
| 前端持续使用 | 登录输入有浏览器长度限制与状态截断；助手保留欢迎语和最近消息，最多 60 条；后台运行数据请求完成后才安排下一次刷新，卸载时中止请求；波形缓冲保留原有 1000 点上限。 |
| 数据库和部署 | 数据库连接池和连接/读写超时有上限，SQLite 开启 WAL 和外键。创建账号的唯一键竞争返回 409，告警确认使用原子条件更新。Nginx 增加慢请求超时和连接限制，保留 20MiB 文件上传并为 multipart 留出 1MiB；服务配置限制 WebSocket 消息大小和接收队列。 |

正常页面内容不依靠删除 SQL 关键字或 HTML 字符保护；合法文本仍原样保存、按文本展示。超出资源边界的请求明确返回 4xx/503，并可稍后重试。校准模型与回放模型依赖未变更。

部署时同时更新后端锁定依赖、前端完整 `out/`、Nginx 和 systemd 配置。前端必须运行 `npm ci` 和 `npm run build`；脚本生成并插入 CSP meta，还生成 `out/security-headers.conf`。Nginx 引用本次构建的该文件，提供包括 frame-ancestors 在内的 HTTP 安全头；不要将不同构建的哈希和 HTML 混用。若配置跨域 API，在构建时提供 `NEXT_PUBLIC_API_BASE_URL`，CSP 会允许该 API 及对应 WebSocket 来源。

本次没有修改数据库表结构，无新增迁移。`deploy/update-security.sh` 为既有生产安装准备独立的锁定依赖环境，检查无运行中回放，停止后端后备份数据库、用户文件与配置，再原子切换版本、检查并重载 Nginx、启动单 worker 后端，最后运行部署业务验收；失败恢复旧代码、依赖和服务配置。旧环境保留，生产秘密和账号不覆盖。后端重启沿用既有停止设备、关闭旧实时会话的行为。

限流和实时状态按单进程维护，沿用现有单 worker 架构；扩展多个 worker/节点需要共享限流与实时状态。默认容量是保护边界，不代表已测得支持 100 个同时推理用户。公网大流量攻击仍需服务器和入口层的容量治理。
